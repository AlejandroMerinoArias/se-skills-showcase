# E-38 — Lantern publication gaps of up to 2.15 s (and E-35, set-point stamp gaps every 32.8 s)
## Question
What delays the 1 Hz lantern publication by up to 2.15 s in the runs since 2026-10-02 03:59, and is it the same
cause as the periodic set-point stall of E-35?
## Command
- Lantern-message gaps against the planner's busy intervals and the monitor's depth and semantic arrivals
  (`monitor.json`), per run.
- Repository changes between the last clean run (20261002-032112) and the first affected one (20261002-035915).
- During live runs: `scratchpad/hiccup.py` (a WSL process sleeping 10 ms, reporting late wake-ups) and a
  `/realsense/depth/camera_info` arrival probe (ROS_DOMAIN_ID 42), with different host programs open.
## Raw results
- Lantern gaps over 1.3 s: 0 in the runs up to 20261002-032112, 8-58 per run from 20261002-035915 on. About one in
  five falls inside an explore plan, as by chance (planner busy 27-30 %); E-37's fix did not change them (53 gaps).
- At every lantern gap the monitor also received no depth or semantic frame for 0.9-1.0 s; these stops start
  10-71 s into a run and repeat every 32.7-33.2 s, also on the approach before exploration.
- Between the clean and the first affected run only `se/` files changed.
- Live probes: the WSL process never woke more than 0.2 s late (140 s) while the simulator's depth frames stopped for
  0.98-1.01 s every 33.1-33.2 s (Chrome and Discord open) and for 0.69-0.73 s every 32.7-32.8 s (Chrome closed).
- The lantern node's 10 s stats timer was at most 0.98 s late; set-point stamp gaps (E-35) follow the same period.
## Verdict
VERDICT: a periodic stall of the simulator's sensor output, about 1 s every 33 s, that began on the host between
03:21 and 03:59 on 2026-10-02 and depends on other host programs; the UAV software is unchanged across the clean and
affected runs and WSL processes keep running. E-35 is the same stall. With Chrome closed, run 20261002-200007
passed the lantern publication test (6 gaps over 1.2 s, all under 1.5 s).
## Limits
The host-side cause is not identified (Discord was open in every probe). The sim test measures lantern messages
where the monitor receives them.
